# Kit — Writing & content (`escrita`)

## Summary
For long-form writing projects: blog posts, books, essay collections, newsletters treated as a single body of work rather than a recurring production line.

## When to choose this type
The deliverable is prose meant to be read, and the main working risk is voice consistency and misattributing authorship to the AI — not technical regressions.

## Standard folders
- `drafts` / `rascunhos` — work in progress.
- `references` / `referencias` — sources, citations, inspiration.
- `published` / `publicado` — final, shipped text.

Defaults: drafts and references checked, published unchecked (nothing is published on day one).

## Anchor file
None currently. A lightweight "editorial brief" (audience, tone, publishing cadence, style rules) could work well here, similar to what `marketing` and `course` now have — worth considering as a future addition rather than leaving this type without an anchor indefinitely.

## Stack / limits placeholders (current)
- Stack example: "Markdown · published on Medium (PT/EN)"
- Limits example: "keep a first-person tone · never present the AI as the text's author"

## Notes for the generator
- This is the type where the product's core rule ("the AI is a tool, not a creative entity with agency" — see CONTEXT.md) is most directly user-facing: the default limits placeholder exists specifically to remind the user to state this in their own words.
- Distinct from `podcast` (proposed): both are content-creation types, but `escrita` is text-only/asynchronous while `podcast` involves recording, editing, and episodic release cadence.
