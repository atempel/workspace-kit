## 2026-07-29 — Git layer: the unblocked half built, the PR/worktree half deliberately not
- **Decision:** `core/git.js` implements the part of docs/specs/git-integration-layer.md (→ #79) that no open question gates — file-state tracking, the safe-edit substrate, the plain-language change summary, and the templated commit message — plus a `workspace-kit status` command. The **PR flow and worktree management are not built**, because each is gated on a "(Product — Alexandre)" question in the spec: hosting-provider scope (GitHub-only via `gh` vs. provider-agnostic) and worktree placement/naming (auto-placed by convention vs. prompted). Both answers determine the implementation, so building ahead of them means throwing a version away.
- **Decision:** when a file is staged *and* has further unstaged edits, it reports as `modified-unstaged`. The unrecorded change is the one a caller about to overwrite the file needs to know about; reporting `staged` there would make the safe-edit check quietly wrong in exactly the case it exists for.
- **Decision:** git is driven by `execFileSync` with explicit argument arrays, never a shell string. A test writes a file named `a file; echo pwned > owned.txt.md` and asserts it is reported literally and nothing executes.
- **Reason for the guardrail tests:** #79's model-agnostic requirement and its "the HTML artifact is unchanged" requirement are both product rules that are easy to violate later by accident. Each is now a test — one asserting `core/git.js` contains no outbound call and depends only on `child_process`/`path`, another asserting `src/workspace-kit.html` never references this feature.
