## 2026-07-29 — "project type" → "kit" rename executed; generated text deliberately excluded
- **Decision:** the rename decided 2026-07-26 is executed. Workspace//kit's own surface now says **kit** everywhere: `KIT_CONFIG` (both copies of the generation logic), `applyKitDefaults`/`populateKitSelect`, the DOM ids `pkit`/`pkitLabel`, the form label "Kit" in both EN and PT, the `kit` input key on `core/generator.js`'s `generate`/`buildFileMap`/`buildStarterPrompt` API, `core/fixtures.json` inputs, `core/parity-check.js`, `research/kits/` (renamed from `research/project-types/`), and README/CONTEXT/specs wording.
- **Decision (scope boundary, new here):** the text workspace//kit **generates** is *not* renamed — a generated `PROJECT.md` still has a `## Project type` heading and the starter prompt still says `Project type:` / `Tipo de projeto:`. **Reason:** the 2026-07-26 rationale was (a) avoiding a collision with the user-authored Templates feature (#32) and (b) not shipping "project type" as a public CLI flag (#20). Neither reaches inside a generated workspace. That text is read by people and agents who have never heard of workspace//kit, for whom "project type" is self-explanatory and "kit" is unexplained product jargon — leaking the product's internal vocabulary into every user's files would cost clarity for no stated benefit.
- **Consequence, used as the test:** because generated output is unchanged, `core/fixtures.json`'s recorded `expected` blocks were left untouched and `npm run test:fixtures` + `npm run test:parity` both still pass. A rename that changed any generated workspace would have failed them. This is the evidence the refactor is behavior-preserving, not just a claim.
- **Alternatives considered:** renaming the generated headings too, for one consistent vocabulary end-to-end — discarded per the reasoning above, but cheap to reverse: it is two string pairs in each copy of the generation logic plus re-recording the fixtures. Flagged in TASKS.md as the owner's to overrule.
- **Timing:** deliberately before the CLI (#20) ships, per the 2026-07-26 entry — after that, `--type` would be a public interface and the rename a breaking change.
- **Process note:** CLAUDE.md asks for plan mode or an equivalent review step before structural changes to `src/workspace-kit.html`. This landed as a reviewable draft PR instead of an unattended push to `main`, with the parity suite as the mechanical check — the rename touches identifiers and two UI strings, not the file's structure.
- **Also in this pass:** `index.html` (the GitHub Pages copy of the artifact) had silently fallen a version behind — it never received the PT starter-prompt fix from 2026-07-27. Re-mirrored from `src/workspace-kit.html`. Worth a convention: that copy is a build output and should be re-mirrored in the same commit that touches the artifact, otherwise the published page drifts unnoticed.
