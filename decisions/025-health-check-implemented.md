## 2026-07-29 — Workspace health check implemented; the doctor judges, the inspector reports
- **Decision:** docs/specs/workspace-health-check.md (→ #78) is implemented as `core/doctor.js` plus a `workspace-kit doctor` command in `bin/workspace-kit.js`. `diagnose()` takes an **inspection index, not a folder path** — it never walks the filesystem itself. That keeps `core/inspect.js` the single module in this codebase that touches the disk, and makes the boundary enforceable rather than aspirational (a test asserts `doctor.js` never requires `fs`).
- **Decision (was an Open Question):** threshold **banding** around #34's ~300-line anchor is *warning at 90% of the limit, over-budget past it*. That satisfies #78's own acceptance criterion (250 healthy / 300 warning / 400 over-budget) and leaves one knob (`warnRatio`) to retune instead of three separate numbers. Thresholds are overridable per call and via `--max-lines`, per the spec's P1.
- **Decision (was an Open Question):** **stale-instruction detection is scoped to the mechanically-detectable case** — an instruction section containing a reference to a file that does not exist. #78's own Open Questions propose exactly this for v1; judging an instruction "obsolete but still linked" needs real usage data, so it is not guessed at.
- **Decision:** skills (`.claude/skills/**`) are **excluded from the always-loaded budget**. A SKILL.md is read when the skill is invoked, not at session start, so counting it would inflate the very figure the budget exists to protect.
- **Found by dogfooding:** the first run against this repo returned verdict `needs-attention` alongside the line "No suggestions — this workspace is within every threshold", because a *warning*-level finding produced no suggestion. A warning with nothing to do about it is noise. Warnings now carry their own low-severity suggestion, and the all-clear line is only printed when the verdict actually is healthy. Regression test: `P0-5e`.
- **Alternatives considered:** having the doctor read files itself for convenience — discarded, it would create the second workspace parser #77 exists to prevent; hardcoding the banding rather than deriving it from a ratio — discarded, the anchor is fixed by #34 but the banding is explicitly the owner's to retune.
