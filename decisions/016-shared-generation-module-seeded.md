# 2026-07-22 — Shared generation module seeded standalone, HTML artifact deferred
- **Decision:** `core/generator.js` was created as the shared generation engine mandated by the "2026-07-21 — Shared generation engine" decision above — plain Node-compatible JS (UMD-lite: `module.exports` for Node, `window.WorkspaceKitCore` for `<script>`), zero dependencies, no build step. It is a **copy-derived seed** of the pure data/generation logic already in `src/workspace-kit.html`'s `<script>` (the 17-type `TYPE_CONFIG`, `.gitignore`/agent-file/starter-prompt builders), with DOM reads (`els.*`, global `LANG`) replaced by explicit function parameters — same behavior, verified against fixture cases (`core/fixtures.json` + `core/check-fixtures.js`). `src/workspace-kit.html` itself is **not modified** and is **not wired to this module** — it keeps its own separate inline copy of the same logic.
- **Reason:** the natural approach (`workspace-kit.html` loading the module via `<script src="...">`) was proposed and explicitly rejected by the owner: it would break using `workspace-kit.html` as a **standalone artifact pasted directly into Claude.ai**, which has no relative-path filesystem access to load a sibling file (see CONTEXT.md — the HTML surface must stay self-contained inside Claude.ai/the browser). The owner's call: preserve that use case as-is; let the shared module exist purely for the CLI (and later Web App) to consume from day one. Going forward, generation-logic improvements get manually ported into the HTML's inline copy when it's easy to do so; otherwise they stay app-only (CLI/Web App), diverging from the artifact by design rather than by accident.
- **Alternatives considered:** `<script src="core/generator.js">` in the HTML — discarded, breaks the Claude.ai-pasted-artifact use case; a small Node/string-concat build step producing a bundled standalone HTML with the module inlined — discarded for now as more machinery than justified by today's need, revisit if manual-backport drift between the two copies becomes painful in practice.
- **Resolves:** the open engineering question left in the "2026-07-21 — Shared generation engine" decision and in `docs/specs/cli-generator.md`'s Open Questions ("exact technical shape of a module includable both via `<script>` and via Node `require`/`import`").
