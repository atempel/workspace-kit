# Local Web App gets its own stack and visual identity (React/Tailwind/shadcn), scoped per surface

**Date:** 2026-07-28

- **Decision:** the Local Web App (#29) is built with **React + Tailwind + shadcn/ui**, with a build step. This is the explicit decision AGENTS.md's "don't add a build framework without an explicit decision" limit asks for — and it is **scoped to that surface only**. The standalone HTML artifact (`src/workspace-kit.html`) keeps its hard "single file, no build step, no framework" constraint unchanged, and `core/generator.js`/`core/inspect.js` keep their zero-dependency, no-build convention so both the CLI and the Web App can consume them. The limit in AGENTS.md is therefore now per-surface, not project-wide.
- **Reason:** a high-fidelity Claude Design prototype ("Workspace Kit Dashboard," 2026-07-27/28) was built on shadcn/ui and covers all five 2026-07-26 lifecycle features as one screen. Rebuilding that in framework-free HTML/CSS/JS would discard working markup and make the dark/light theming — which `DESIGN.md` treats as equally first-class, not a bolt-on — substantially harder for no benefit the artifact's constraint was protecting: that constraint exists so the artifact can be pasted into Claude.ai as a self-contained file, which has never applied to a locally-served app.
- **Decision:** the Web App's visual identity is the prototype's direction — neutral shadcn token base, Inter for UI text, JetBrains Mono for paths/metrics, one accent (amber/teal), status semantics fixed as green/amber/red plus a muted neutral, always color + icon + label together. This is logged rather than assumed, per CONTEXT.md's rule that brand changes are recorded, not made silently. It deliberately **does not** override `decisions/008-v2-visual-identity.md`: the artifact's terminal identity stands, and the two surfaces are allowed to read as related-but-distinct products (one-shot artifact vs. ongoing management app).
- **Alternatives considered:** reimplementing the prototype's look framework-free to preserve a single project-wide constraint — discarded, see Reason; deferring the stack choice to implementation time — discarded, it determines whether the prototype's code is reusable at all, so leaving it open would have made the prototype decorative rather than a head start.
- **Also in this pass:** `docs/specs/web-app-dashboard.md` written as the bridge spec between the prototype and the five lifecycle specs (#77–#81) — it owns rendering only, never domain logic; `docs/specs/local-web-app.md`'s "Design-system-level polish" Non-Goal retired as obsolete; the prototype's markup versioned at `docs/design/workspace-kit-dashboard.dc.html` (the full Claude Design export, including its ~650KB bundle, deliberately not committed).
