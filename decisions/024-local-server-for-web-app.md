## 2026-07-29 — Local Web App reaches the filesystem through a local Node server
- **Decision:** the Local Web App (#29) talks to the filesystem via a **local Node server**, not the browser's File System Access API. Confirmed by the owner 2026-07-29, closing the question left open in both docs/specs/local-web-app.md (→ #29) and docs/specs/web-app-dashboard.md (→ #169).
- **Reason:** `core/inspect.js` uses Node's `fs`, and every module built on it (`core/doctor.js`, the planned `core/git.js`) inherits that. The File System Access API could not execute any of them — choosing it would have meant rewriting `core/` against an abstract file backend and giving up the property that the CLI and the Web App run literally the same code. Git operations (#79) settle it independently: a browser cannot drive git at all.
- **Consequence:** the dashboard is a client of a small local HTTP surface over `core/`, not a reimplementation of it. Anything the Web App can compute, the CLI can too, by construction.
