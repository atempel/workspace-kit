01O que existe hoje

O projeto tem duas metades. A de escrita — que gera workspaces — já existia. A de leitura, que abre e avalia um workspace existente, foi construída inteira em 29/07, em seis PRs mergeados em main.

Metade de escrita — gera workspaces

src/workspace-kit.html — o artefato standalone, arquivo único, sem build.
core/generator.js — cópia compartilhada da lógica de geração, para o CLI e o Web App consumirem.

As duas cópias são deliberadamente separadas (ver DECISIONS.md, 2026-07-22). O que impede elas de divergirem é o teste de paridade: ele carrega o HTML real num jsdom e compara a saída dos dois, byte a byte, para os mesmos inputs.

Metade de leitura — abre e avalia um workspace

MóduloO que fazTestes
core/inspect.js Indexa a pasta: métricas por arquivo, instruções parseadas em unidades de ID estável, grafo de referências cruzadas. Também parseia queue/*.md e SESSIONS.md. É o único módulo do código que toca o disco. 21
core/doctor.js A camada de julgamento: thresholds, veredito e sugestões concretas. Recebe o índice pronto, nunca um caminho de pasta — é isso que mantém a fronteira com o inspect nítida. 16
core/git.js Estado dos arquivos, checagem de edição segura, resumo de mudanças em linguagem simples e mensagem de commit templatada. Model-agnostic é regra de produto aqui: um teste garante que o módulo não faz nenhuma chamada externa. 11
core/server.js Superfície JSON read-only que o dashboard vai consumir. Zero dependência, só 127.0.0.1, recusa caminhos que escapem da raiz e recusa todo método que não seja GET. 9
bin/workspace-kit.js O CLI: doctor, status, serve, inspect. —

04Próximos passos desbloqueados

1. O front-end do dashboard #169

É o próximo passo natural. A camada de dados está 100% pronta: todo número que docs/specs/web-app-dashboard.md renderiza já é servido pelo core/server.js. O que falta é converter docs/design/workspace-kit-dashboard.dc.html — o export do Claude Design — para React + Tailwind + shadcn.

Os flags capabilities no payload existem exatamente para o UI mostrar os controles de PR e worktree como indisponíveis, em vez de desenhá-los como se funcionassem.

2. A metade de geração de #80 #81

Emitir SESSIONS.md, a instrução permanente e a convenção queue/ nos workspaces gerados. A metade de leitura já está pronta; esta não foi feita de propósito: muda a saída gerada nas três superfícies, exige regravar as fixtures e um backport manual para a cópia inline do src/workspace-kit.html — que o CLAUDE.md pede que seja revisado, não aplicado sem supervisão.

3. Push travado por credencial corrigido — não era verdade

Este item estava errado na primeira versão deste relatório e foi corrigido. A primeira versão dizia que o branch worktree-workflow-sync-fix estava travado por falta do escopo workflow no token, e pedia um gh auth refresh. Isso não era mais verdade quando o relatório foi escrito.

O que é fato: o fix já está em main — commit 562e78a, mergeado pelo PR #183. .github/scripts/sync_specs_to_issues.py está no lugar e o workflow dispara por push em main. Não havia nada para enviar.

Origem do erro: o item foi copiado de uma entrada do SESSIONS.md escrita antes daquele merge, e não foi verificado contra o estado real do repositório — exatamente o que a regra "diga o que foi verificado rodando" em reports/README.md existe para impedir.
